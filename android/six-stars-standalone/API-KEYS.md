# API/provider access for The Last Cat: the Six Stars

The standalone app can mix hosted LLM/ASR with either hosted or local TTS. This is intentional: Google AI Studio and Groq can be used directly for development while speech is generated by the existing Qwen3-TTS service running on the desktop.

## Local TTS + direct Google/Groq development mode

This is the cheapest development configuration when the phone and desktop are on the same trusted LAN.

1. Start the repository's normal local Qwen3-TTS WebSocket service. The desktop launcher uses `scripts/websocket_tts_server.py` on port `8100` and the service binds to `0.0.0.0` by default.
2. Find the desktop computer's LAN IPv4 address.
3. Make sure TCP port `8100` is allowed through the desktop firewall for the trusted/private network.
4. Copy `app/src/main/assets/standalone-services.local.json.example` to `app/src/main/assets/standalone-services.local.json`.
5. Keep `Proxy.Enabled=false` and add the Google/Groq keys.
6. Set TTS to local and point it at the desktop LAN address:

```json
{
  "LLM": {
    "ApiKey": "YOUR_GOOGLE_AI_STUDIO_KEY"
  },
  "ASR": {
    "ApiKey": "YOUR_GROQ_KEY"
  },
  "TTS": {
    "Mode": "local",
    "LocalWebSocketUrl": "ws://192.168.1.50:8100/tts/stream"
  },
  "Proxy": {
    "Enabled": false
  }
}
```

Do **not** use `localhost` or `127.0.0.1` on a physical phone; those addresses refer to the phone itself.

The Android client speaks the same `generate` WebSocket protocol as desktop `WebSocketTtsVoiceGenerator`. It sends the Star id, `voiceId`, `voiceCloneAudioFile`, `voiceCloneRefText`, language, VoiceClone task type, and the already sentence-sized text chunk. The desktop-side service resolves the clone WAV from its normal `QWEN_TTS_CLONE_AUDIO_DIR`.

### TTS Mode behavior

`TTS.Mode` supports:

- `local`: require `LocalWebSocketUrl`; never spend hosted TTS quota.
- `hosted`: require Alibaba/DashScope directly or through the Cloudflare proxy.
- `auto` (default): if `LocalWebSocketUrl` is non-empty, use local TTS; otherwise use hosted TTS.

`auto` does **not** silently fall back to hosted TTS when a configured local service is unreachable. This is deliberate so a local outage cannot unexpectedly create hosted TTS charges.

The local service currently uses unencrypted `ws://` on the LAN. The app permits cleartext traffic for this development path. Use it only on a trusted/private network; hosted provider and Cloudflare requests remain HTTPS.

## Hosted TTS direct developer mode

If you want to test Alibaba instead, use:

```json
{
  "TTS": {
    "Mode": "hosted",
    "ApiKey": "YOUR_DASHSCOPE_KEY",
    "LocalWebSocketUrl": ""
  }
}
```

The real `.local.json` file is git-ignored.

## Recommended production mode: Cloudflare proxy

The phone does **not** need the Google/Groq/DashScope provider keys.

Configure:

```json
{
  "Proxy": {
    "Enabled": true,
    "BaseUrl": "https://api.your-domain.example",
    "AccessToken": "YOUR_APP_PROXY_TOKEN"
  },
  "TTS": {
    "Mode": "hosted",
    "LocalWebSocketUrl": ""
  }
}
```

The Worker project is at `cloudflare/six-stars-ai-proxy`. Provider billing keys are stored as Cloudflare Worker secrets there.

The `AccessToken` is only an app-to-proxy gate. Because the APK must possess it, treat it as a temporary/casual-abuse control; later production hardening should issue short-lived app sessions after Play Integrity or another attestation mechanism. The provider billing keys never need to be shipped in the APK.

The future Settings screen can write the device-private override at `<app files>/config/standalone-services.local.json`; runtime settings already support that location now.

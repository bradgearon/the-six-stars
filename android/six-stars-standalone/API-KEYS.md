# API/provider access for The Last Cat: the Six Stars

The standalone app can mix hosted LLM/ASR with either hosted or local TTS. This is intentional: Google AI Studio and Groq can be used directly for development while speech is generated by the existing Qwen3-TTS service running on the desktop.

## Preferred local TTS + direct Google/Groq development mode

Use the existing desktop application's mobile bridge as the local TTS boundary. Android sends only `starId` and the sentence. The .NET host loads the canonical Star profile, resolves `voiceCloneAudioFile` with the same desktop path resolver used by normal speech, and then invokes the normal local qwentts.cpp HTTP TTS generator.

1. Start the desktop Last Cat/Six Stars application and its normal local Qwen3-TTS service.
2. Start the desktop Mobile Bridge (normally port `8066`).
3. Find the desktop computer's LAN IPv4 address and allow the bridge/TTS ports through the private-network firewall as you normally do for the thin client.
4. Copy `app/src/main/assets/standalone-services.local.json.example` to `app/src/main/assets/standalone-services.local.json`.
5. Keep `Proxy.Enabled=false`, add the Google/Groq keys, and configure the desktop local-TTS service URL:

```json
{
  "LLM": {
    "ApiKey": "YOUR_GOOGLE_AI_STUDIO_KEY"
  },
  "ASR": {
    "ApiKey": "YOUR_GROQ_KEY"
  },
  "TTS": {
    "Mode": "local",
    "LocalServiceUrl": "http://192.168.1.179:8066/api/mobile/local-tts"
  },
  "Proxy": {
    "Enabled": false
  }
}
```

Do **not** use `localhost` or `127.0.0.1` on a physical phone; those addresses refer to the phone itself.

The request contract is intentionally tiny:

```json
{
  "starId": "Elusiaa",
  "text": "The sentence to speak."
}
```

The Android app does not send a clone filename/path in this route. The desktop owns that detail, so relative Android content paths cannot leak into `websocket_tts_server.py`.

### Legacy direct Python WebSocket route

`TTS.LocalWebSocketUrl` is retained for development compatibility with `ws://<desktop>:8100/tts/stream`, but it is no longer the preferred path because the Python service correctly requires a host-valid absolute clone-audio path. Prefer `LocalServiceUrl` unless you deliberately control the payload/path yourself.

### TTS Mode behavior

`TTS.Mode` supports:

- `local`: require either `LocalServiceUrl` (preferred) or `LocalWebSocketUrl` (legacy); never spend hosted TTS quota.
- `hosted`: require Alibaba/DashScope directly or through the Cloudflare proxy.
- `auto` (default): if either local URL is configured, use local TTS; otherwise use hosted TTS.

If both local URLs are present, `LocalServiceUrl` wins.

`auto` does **not** silently fall back to hosted TTS when a configured local service is unreachable. This is deliberate so a local outage cannot unexpectedly create hosted TTS charges.

The local bridge currently uses unencrypted `http://`/`ws://` on the LAN. The app permits cleartext traffic for this development path. Use it only on a trusted/private network; hosted provider and Cloudflare requests remain HTTPS.

## Hosted TTS direct developer mode

If you want to test Alibaba instead, use:

```json
{
  "TTS": {
    "Mode": "hosted",
    "ApiKey": "YOUR_DASHSCOPE_KEY",
    "LocalServiceUrl": "",
    "LocalWebSocketUrl": ""
  }
}
```

The real `.local.json` file is git-ignored.

## Recommended production mode: Cloudflare proxy

The phone does **not** need the Google/Groq/DashScope provider keys.

Configure:

```json
{
  "Proxy": {
    "Enabled": true,
    "BaseUrl": "https://api.thelastcat.net",
    "AccessToken": "YOUR_APP_PROXY_TOKEN"
  },
  "TTS": {
    "Mode": "hosted",
    "LocalServiceUrl": "",
    "LocalWebSocketUrl": ""
  }
}
```

The Worker project is at `cloudflare/six-stars-ai-proxy`. Provider billing keys are stored as Cloudflare Worker secrets there.

The `AccessToken` is only an app-to-proxy gate. Because the APK must possess it, treat it as a temporary/casual-abuse control; later production hardening should issue short-lived app sessions after Play Integrity or another attestation mechanism. The provider billing keys never need to be shipped in the APK.

The future Settings screen can write the device-private override at `<app files>/config/standalone-services.local.json`; runtime settings already support that location now.

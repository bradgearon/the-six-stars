# First Chunk Prefetch TTS Update

The WebSocket Qwen TTS server now defaults to a safer low-latency chunking strategy.

## What changed

- The server no longer starts every chunk generation task at once by default.
- Default mode is now `first_then_prefetch`.
- Chunk 1 is generated by itself and sent to the WPF client immediately.
- As soon as chunk 1 is sent, chunk 2 begins generating while chunk 1 is already playing.
- Remaining chunks are sent back in order.
- This avoids the local Qwen model/GPU contention that can make the first chunk delayed, silent, or unreliable when every chunk is generated in parallel on one model instance.

## Default environment

```bat
set QWEN_TTS_CHUNK_GENERATION_MODE=first_then_prefetch
set QWEN_TTS_PARALLEL_CHUNKS=false
```

## Optional modes

Safest default:

```bat
set QWEN_TTS_CHUNK_GENERATION_MODE=first_then_prefetch
```

Generate first chunk alone, then generate remaining chunks with bounded parallelism:

```bat
set QWEN_TTS_CHUNK_GENERATION_MODE=first_then_parallel
set QWEN_TTS_AFTER_FIRST_MAX_PARALLEL_CHUNKS=2
```

Legacy all-at-once parallel mode:

```bat
set QWEN_TTS_CHUNK_GENERATION_MODE=parallel
set QWEN_TTS_MAX_PARALLEL_CHUNKS=0
```

Fully sequential fallback:

```bat
set QWEN_TTS_CHUNK_GENERATION_MODE=sequential
```
